title: Reranking
description: A cross-encoder scores query and document together. Requires rank pooling, returns original indices, and the scores are raw logits.
---

import { Tabs, TabItem } from '@astrojs/starlight/components';

A reranker reads the query and the document **together, in one forward pass**, and emits a
relevance score. An embedding model never sees them together: it compresses each into a
vector separately and you compare the vectors afterwards.

That difference is the whole point. Cosine similarity has to survive compression into a few
hundred dimensions computed without knowing the question; a cross-encoder attends between
the query's tokens and the document's. So: retrieve 100 candidates with vectors because it
is cheap and index-friendly, then rerank the top 100 down to 5 because it is accurate. In
that order, and only in that order — a cross-encoder over a whole corpus is one forward pass
per document.

Ask for fewer: `topN` / `top_n` / the third argument returns only the best N. The model
still scores every document — this trims the result, not the work.

## `rank` pooling, or nothing

`Rerank` **requires** a model opened with `pooling: "rank"`. That pooling type is what
attaches the model's classification head to the graph; without it there is no head to read.

Call it on a `mean`-pooled engine and you get a typed error, not a number:

later, by someone else.

## Read the result correctly

Results come back **sorted best-first**, which means they are no longer in your order.
`index` is the document's position in the list **you passed in**. Use it to map back; never
assume result *i* is document *i*.

`score` is a **raw model logit**:

- Comparable **within one call**. Higher is better; the ordering is the product.
- Not comparable across models. A different reranker has a different scale.
- Not a probability. Do not threshold at 0.5, and do not show it to a user as a percentage.
- Negative is normal. Verified across all bindings on one query: `+6.591`, `−5.161`,
  `−11.004` — same model, same three documents, byte-identical in every language.

If you need a cutoff, calibrate one on your own data against your own model, and re-do it
when you change either.

Behaviour comes from adapters, not from vectors.
